## Question 1

Routing pi as a fifth provider would give Hydra a child it can launch and record, and the gate would stay outside that child. The [command-line page](https://pi.dev/docs/latest/cli) gives the flags: a terminal starts interactive mode, `-p` or `--print` is print mode, `--mode json` writes JSONL and exits, and `--mode rpc` reads JSONL commands until shutdown. JSON and RPC emit `tool_execution_start` with `toolCallId`, `toolName`, and `args` ([JSON Event Stream](https://pi.dev/docs/latest/json)). The [agent-core README](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md) says the `beforeToolCall` hook "runs after `tool_execution_start`" and "can block execution", so an outside reader sees the call too late to be the gate. The [extensions page](https://pi.dev/docs/latest/extensions) puts the same block inside the process: a `tool_call` handler may return `{ block: true, reason }`. The [repo README](https://github.com/earendil-works/pi/blob/main/README.md) states the permission story as "Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access. By default, it runs with the permissions of the user and process that launched it." pi-ai authenticates with API keys and with OAuth for Anthropic, OpenAI, GitHub Copilot, and OpenRouter ([packages/ai/README.md](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md), "OAuth Providers"), which is the raw-model plane D4 and D16 already fence off. Codex, which already spoke a `PreToolUse` hook, still cost one session, 14 files, and 1,365 insertions (`.scratch/hydra/build/48-codex-as-the-fourth-provider.md`), and pi has no outside hook to point at `gate.py`.

### Recommendation

Leave pi off the provider list. `--mode json` and `--mode rpc` are enough to launch and record a run, and they are not enough to gate one: the only block is an in-process callback, and an extension that called the gate would run with the agent's own rights. The useful borrow is the local endpoint, which question 3 uses.

## Question 2

A harness of our own needs the three things a Hydra provider already has: a way to start it, the hook payload the gate already reads, and a JSONL stream a normalizer can turn into a record. `src/policy/replay.rs` builds that payload as `hook_event_name`, `tool_name`, `tool_input`, and `cwd`, and `src/provider/*.rs` builds argv and points a hook command at the compiled gate. Pi's own shape, from [How Pi Works](https://pi.dev/docs/latest/how-pi-works), is a loop that "records the response, executes each tool call, and records the results", with sessions as JSONL trees where "each tree entry has an ID and refers to its parent." The repo splits that into `@earendil-works/pi-ai` (the LLM API), `@earendil-works/pi-agent-core` (the loop), and `@earendil-works/pi-coding-agent` (the CLI), with `pi-tui`, `pi-durable`, `pi-telemetry`, and `chord` beside them ([README](https://github.com/earendil-works/pi/blob/main/README.md)). Copy the default tools the [command-line page](https://pi.dev/docs/latest/cli) still names, `read`, `bash`, `edit`, and `write`, plus "primitives, not features" from [pi.dev](https://pi.dev/), print mode for a one-shot run, and RPC only when a parent must steer a live process. Leave out in-process extensions: the same how-it-works page says they are "TypeScript modules loaded into the Pi process" and "Extensions execute inside that process." The [license](https://github.com/earendil-works/pi/blob/main/LICENSE) is MIT, "Copyright (c) 2025 Mario Zechner", and on `main` `packages/agent/src/agent-loop.ts` is 29,088 bytes and `agent.ts` is 19,748 bytes, against 14,727,773 bytes of TypeScript in the whole repo.

### Recommendation

Build the loop in Rust against the existing gate payload and the existing record. Treat pi as a checklist: four default tools, an append-only JSONL session, print mode, and no extension loader. The parent-pointer tree and RPC can wait until a run needs to branch or be steered.

## Question 3

The smallest cut is a Rust loop that posts to an OpenAI-compatible `/v1` chat endpoint, runs only `read`, `write`, `edit`, and `bash`, and writes a JSONL record the contract already accepts. pi-ai documents that local shape as `api: 'openai-completions'` and `baseUrl: 'http://localhost:11434/v1'`, says "keyless local servers resolve as configured with no key", and lists "Any OpenAI-compatible API: Ollama, vLLM, LM Studio, etc." ([packages/ai/README.md](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md)). Ollama's own page shows the same URL in `~/.pi/agent/models.json` with `"api": "openai-completions"` ([docs.ollama.com/integrations/pi](https://docs.ollama.com/integrations/pi)). Before each tool runs, the loop sends the payload `replay.rs` already builds and takes the gate's answer. The record holds the tool call, the tool result, and the decision, and nothing else is in the cut: no TUI, no RPC server, no extension loader, no MCP, no compaction. Ticket 87's attempt step today asks Gemma through Ollama and stores a sentence. This cut is what lets an attempt include a gated tool call, so a verifiable task can score a refusal. It stays a batch beside the apprentice, off the provider list, run when no other agent is alive.

### Recommendation

Cost: one session, the same shape as build 48's single coding session (14 files, 1,365 insertions), spent on the loop, the four tools, one gate check per call, and a test that reads the record back. A second session appears only if that JSONL cannot reuse a normalizer that already exists. For ticket 87 this makes an attempt that acts under the gate and can be graded on the refusal, while the weekly panel, the pairs file, and the LoRA wait stay as that ticket left them.
